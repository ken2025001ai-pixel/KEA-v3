## 问题背景

Phase 7 和 Phase 8 的 subagent 均需自行读取多个目录（LOGIC_DIR / OBJECTS_DIR / ACTIONS_DIR）来建立链接注册表和关系声明。与 Phase 5/6 改造前一样，违反了 CLAUDE.md 原则："Controller 负责准备上下文，不让 subagent 自己找文件"。

两个 Phase 的候选预扫描已是正确模式（Phase 文件主 session 自己做）：
- Phase 7 Step 3 已收集 `REFERENCED_ACTIONS`（动作名+引用计数）
- Phase 8 Step 1/2 已收集 `RULE_CANDIDATES`（名称+类型+来源+条件文本，经用户确认）

缺失的是：将已有文档的结构化索引（Registry）在 Dispatch 前预处理好传入 subagent，替代让 subagent 逐文件读取。

## 工具能力确认

`kea parse {DIR}` 目录模式已支持，输出包含 id/name/type/properties/relations/inputs/outputs。**无需任何工具层改动。**

## Section 1：Phase 7 改动

### 1.1 Phase 7 新增 Step 2.5

**文件**：`AgentFile/phases/phase-7-extract-actions.md`

**位置**：`### Step 2: 更新 chain-state.md 为 in_progress` 之后，`### Step 4: Dispatch 动作提取 Agent` 之前。

```markdown
### Step 2.5: 预处理逻辑注册表与对象注册表

**工具调用 1**：扫描逻辑文档

```bash

```

```

  输入对象：{对象名1}, {对象名2} ...
  输出对象：{对象名1} ...

{逻辑名} (id={id})
  ...
```

**失败**（count = 0 或命令报错）→ 展示错误详情，询问用户：
- A 检查 LOGIC_DIR 路径后重试
- B 跳过工具扫描（fallback：Step 4 仍传 `LOGIC_DIR`，subagent 自行读文件）

### 1.4 extract-actions SKILL.md 改动

**Source Documents 表**替换为：

| 参数 | 必填 | 说明 |
|---|---|---|
| `REFERENCED_ACTIONS` | **是** | Phase 7 Step 3 收集的动作候选列表（名称+引用计数）。直接以此为提取范围，**不要重新读 LOGIC_DIR**。 |
| `LOGIC_REGISTRY` | **是** | Phase 7 用 `kea parse` 生成的逻辑注册表，含关联动作和输入输出对象。用于填写 `part_of` relations。 |
| `OBJECT_REGISTRY` | **是** | Phase 7 用 `kea parse` 生成的对象注册表，含属性清单。用于 `uses`/`modifies` relation 声明和 `[[链接]]` 校验。 |
| `SUMMARY_PATHS` | 否 | 补充业务上下文（参数描述、异常场景）。 |

移除 `LOGIC_DIR`、`OBJECTS_DIR`、`REPORT_PATHS`。

**Source priority** 改为：`REFERENCED_ACTIONS` > `LOGIC_REGISTRY` > `OBJECT_REGISTRY` > `SUMMARY_PATHS`

**Upstream Artifacts 表**：`LOGIC_DIR` → `LOGIC_REGISTRY`，`OBJECTS_DIR` → `OBJECT_REGISTRY`。

**Step 1 重写**：

```markdown
## Step 1: Read inputs

Read `REFERENCED_ACTIONS` — the pre-computed list of action names and their
reference counts, collected by Phase 7 from logic documents. This is your
complete extraction scope. **Do NOT read files from LOGIC_DIR.**

Read `LOGIC_REGISTRY` — structured logic document index generated by Phase 7
using `kea parse`. Use it to fill `part_of` relations: for each action in
REFERENCED_ACTIONS, find which logic id(s) call it via the "关联动作" field.

Read `OBJECT_REGISTRY` — structured object index generated by Phase 7 using
`kea parse`. Use it for:
- `uses`/`modifies` relation declarations (which objects does this action read/write)
- `[[链接]]` validity: only link to objects listed here. **Do NOT read files from OBJECTS_DIR.**

Read files in `SUMMARY_PATHS` (if provided) for supplementary detail on action
parameters, trigger conditions, and exception scenarios.

**Do NOT read files from LOGIC_DIR or OBJECTS_DIR** — the tools have already done that.
```

**NEEDS_CONTEXT 示例**：将 `LOGIC_DIR 为空` 改为 `REFERENCED_ACTIONS 为空，无动作候选数据`。
